# AGENTS.md

Atmosphère system module that patches other system processes (fs, es, ldr, nifm, nim, erpt, olsc) in memory at boot, plus a Tesla overlay to edit config and view results. C++23 on devkitPro/libnx, aarch64.

Fork of `impeeza/sys-patch` (private remote `eleqian/sys-patch`). Main fork addition is `fs_codepage_patch()` — UTF-8/Chinese filename support — see below.

## Build
- Prereqs: devkitPro with `DEVKITPRO` set, and the libtesla submodule (`git submodule update --init --recursive`).
- Build from the **repo root**: `make` (builds `sysmod` + `overlay`, copies into `out/`); `make dist` also zips; `make clean`.
- After each sysmod build, `make` runs `sysmod/tools/check_patch_sizes.py` (build-time guard): patch function sizes are obtained automatically from `_end` assembly labels placed after each patch function (no manual size macros; sysmod needs `-fno-toplevel-reorder` in CXXFLAGS — without it GCC emits the top-level asm before the deferred function bodies and the computed size is 0). The guard verifies (a) label delta == ELF symbol size, (b) size fits the hole at its fs patch site, and (c) **every hand-written patch instruction decodes to a legal rewrite** (`nop` / `movz` keeping Rd / `add Rd,Rn,w0` with imm6=0 and unchanged Rd,Rn / same-address access-width change) — this class of typo has twice produced undecodable garbage that hung fs at boot. If the fs binary is available (`$FS_KIP1`, else the local RE copy) it also byte-compares every cmp signature. `make check-patch-sizes` runs it standalone. Hole data in the script's `FUNCTIONS` table is derived from Ghidra function boundaries — re-derive when targeting a different fs binary.
- Do **not** run `make -C sysmod` / `make -C overlay` directly. The root Makefile exports `CUSTOM_DEFINES` / `VERSION_WITH_HASH` / build-date defines that the sub-Makefiles require.
- Release version is `export VERSION := 1.5.9` in the root Makefile.
- No tests, lint, or typecheck. Verify by building and checking `/config/sys-patch/log.ini` on device.

## Layout
- `sysmod/` — the system module (title `420000000000000B`). `src/main.cpp` holds the patch table and `fs_codepage_patch()`; runs once at boot, then exits.
- `overlay/` — Tesla overlay GUI (`sys-patch-overlay.ovl`) for config and log. Its Makefile has an `ftp:` target with hardcoded host/credentials — don't run it accidentally.
- `common/minIni/` — INI library shared by both targets.
- Runtime config `/config/sys-patch/config.ini`, log `/config/sys-patch/log.ini`.

## FS codepage patch (fork-specific, high risk)
- `fs_codepage_patch()` replaces fs's CP932 (Shift-JIS)↔UTF-16 routines with UTF-8↔UTF-16 and patches call sites so FAT/exFAT handles 3-byte CJK filenames.
- It is **pattern-driven** — there are **no hardcoded fs offsets**. Since **P1** the tables are **two-level**: `fs_fn_groups[]` (12 groups, one per fs function that gets modified — `p01_IDirectory_Read`, `p05_p17_FAT_GetNextChar`, `p11_p26_WideChar_Compare`, `p06_FAT_GetNextPathComponent`, `p27_FAT_MakeShortName`, `p07_StringDesc_AddLeft`, `p08_StringDesc_GetCharCount`, `p09_StringDesc_CompareUnicode`, `p10_StringDesc_CompareOem`, `p02_p04_PFCODE_Converters`, `p28_PFCODE_Str_Unicode2OEM`, `p29_StringDesc_ToUpper`) names a `[pat_begin,pat_end)` / `[blob_begin,blob_end)` slice, and `fs_cp_patterns[]` (22 entries) / `fs_codepage_blobs[]` (8 entries) are laid out **grouped by function in `FUNC_ORDER`**. Grouping matters because 15 of the 29 patch points live in a single 872-byte function. Per-entry gating (`stage_idx` 0–5, `needs_wide_cmp`) replaced the old `fs_stages[]` — p05/p17 share a function but sit in different semantic stages, and p11–p16 (per-instruction entries, `wide_cmp=0`) vs the **M6** whole-function replacement (`wide_cmp=1`, see below) share a function but differ in `wide_cmp` membership, so gating **cannot** be expressed at group level. A pattern is a byte template where `.` is a wildcard (`REGEX_SKIP`); on a hit the instruction at `i+inst_offset` is read, `cond(inst)` decides, and `patch(inst)` yields the semantically-equivalent instruction written at `addr+inst_offset+patch_offset`. Registers, addresses and widths are **inherited from the matched site**, so register reallocation between FW versions needs no new offsets at all. Logic + tables are **mechanically generated** from the fully verified `PATTERNS.json` (`_pattern_gen.py` → `_gen_cpp.py` → `_cpp_tables.txt` → `_splice_main.py`); fidelity is re-checked offline by `_verify_cpp_table.py` (table == JSON, and on 22 fs binaries: unique hit + landing site + `patch(cmp) == RESOLVED.patch`, **506/506**) and end-to-end by `_audit/_p1_sim_scan.py` (22/22 binaries: hit set + site + write count == `RESOLVED.md`). **Never edit these tables by hand** — regenerate them. ⚠️ `_splice_main.py` **overwrites** `main.cpp`'s fs section from `_new_part1.cpp` + `_cpp_tables.txt` + `_new_part3.cpp`, so hand-edits to that section (structs, helper functions, the patch implementations) must be made in the two part files, not in `main.cpp`; `_split_main.py` re-syncs the part files back from `main.cpp` if you did edit it directly.
- **Predicate bitmap (M3) instead of per-entry byte scanning.** 11 cheap *predicates* (the same `cond(inst)` bodies `rules_is_*`) are baked into `fs_pred_mask(inst, nmask)`; `fs_build_pred_bits()` computes **once per 4 KiB chunk** a bit-plane `fs_pred_plane[11][FS_BIT_WORDS]` (bit *w* = word *w* of the chunk hits that predicate). Each entry then walks only **its own** plane via `ctz` and byte-compares only at those word offsets — cost ≈ `predicates × seglen/4` (build) + `entries × seglen/256` (scan), vs. the old byte probes (~75.5 M → ~6.1 M predicate evals per boot). Because every pattern's landing site satisfies `(hit + inst_offset) % 4 == 0` (506/506 verified), a predicate hit *implies* the pattern can only match at that word, so the old `applied()` "already patched?" callback is **unreachable and has been removed**. ⚠️ **`FS_OVERLAP` must be a multiple of 4** (`0x50`, not `0x4f`): `chunk_base = segment_start − overlap`, and the plane is indexed by the *chunk's* word grid, so an odd overlap shifts that grid off fs's instruction grid and every multi-word pattern silently stops matching. Guarded by `static_assert(FS_OVERLAP % 4 == 0)`. Offline proof of the prefilter equivalence: `_audit/_p1_prefilter_check.py`.
- The old `fs_patch_function()` cmp/patch byte arrays are gone. `patch(inst)` only performs *semantically equivalent rewrites* (`add w,#imm`→`add wD,wN,w0`; `ldrb`→`ldrh`; `orr … lsl #8`→`lsl #16`; `bfi #8,#8`→`#16,#8`; `csel`/`cinc`→`add`; `and #0xffff`→`mov`; `movz #0x2e`→`movz #2`), implemented as `constexpr rules_*()`. A single patch point (the `pNN` in a name) may carry several **variant-family** patterns — e.g. #17–#20 ship both a `bfi` form (16.1.0) and an `orr lsl#8` form (20.x+), #10 has 8-group/14-group families, #28's two families differ in `entry_offset`. Any given firmware matches **only one family**, so a 0-hit sibling is expected, not an error.
- **Safety invariant: exactly one match per pattern per target `.text`.** 0 hits = safe no-write (that point/family is absent); ≥2 hits = the patch could land in the wrong function. The build guard enforces this, plus `cond` satisfaction at the landing site, the `inst_offset % 4 == 0` / `(hit + inst_offset) % 4 == 0` **word-alignment invariant M3 depends on**, the exact-cover (contiguous, non-empty) `fs_fn_groups[]` intervals, and the self-consistency of the predicate table (`FS_PRED_COUNT` ↔ `fs_pred_names[]` ↔ the bit indices in `fs_pred_mask()`, and `fs_pred_names[pred_idx] == cond` for every entry). It judges 0-hits **per patch point** (any sibling family hitting ⇒ the point is covered ⇒ warning only).
- `constinit` cannot hold function pointers (taking a function's address is not a constant expression, nor is `reinterpret_cast`), so `fs_codepage_blobs[]` stores `FsBlobImpl` **enum** values and `fs_blob_range()` switches to the address at runtime. Do not try to put pointers in these tables.
- **ASLR discipline (hard requirement)**: the six replacement functions are copied verbatim into fs's address space, and module load addresses are randomized — Ghidra's/ELF's `0x7100xxxx` values are analysis-time only and mean nothing at runtime. Copied code must therefore be **position-independent and fully self-contained**: no absolute address materialisation, no calls to helpers, no literal pools or external data. Note that `(uintptr_t)&somefunc` is **not** PC-relative under this `-fPIE` build — GCC routes it through `.data.rel.ro`. The build guard's position-independence scan enforces all of the above (it also rejects `BL`, out-of-function `B`, and `MOVZ/MOVK`-built wide constants).
- **fs globals must never be hardcoded — harvest them from the site instead.** `patch_str_unicode2oem` needs the fs code-page context pointer, which fs keeps in a data slot whose **address changes on every firmware** (measured across 22 fs binaries: 19.0.1/exfat=`0x24eb50`, 19.0.1/fat32=`0x240b50`, 16.1.0=`0x2797d0`, 17.0.0=`0x23be90`, 18.x=`0x23d138`, 20.x=`0x263f40`, 21.x=`0x25cbc8`, 22.x=`0x25fc38` — 14 distinct values). The page delta and `ldr` immediate change too, so a hardcoded `adrp`+`ldr` pair is valid on exactly one firmware and dereferences a **bogus pointer** everywhere else. The information is in the bytes we are about to overwrite, so the patcher reads the original function first: `fs_harvest_ctx_pair()` scans the first `0x120` bytes for the original's `adrp xN,page` + `ldr xN,[xN,#imm]`, decodes the slot, and re-encodes the pair as x3 relative to the **placeholder's real address** — so it works even across a page boundary. The two placeholder words in `patch_str_unicode2oem` are sentinels (`0xDEAD0001`/`0xDEAD0002`) that the patcher overwrites; the build guard requires both to be present, adjacent and ordered (it searches by **content**, not by offset — GCC emits the prologue before the inline asm), and requires them to be harvestable from the reference binary. **If harvesting fails the point is skipped entirely** (`FAILED_HARVEST`, original function left intact) — never write code that dereferences an unverified pointer. Offline proof for all 22 binaries: `_audit/_verify_ctx_fix.py` (harvest succeeds, resolves to the same slot, idempotent).
- **Blob-level gating mirrors `FsPat`.** `FsBlob` carries the same `stage_idx` / `needs_wide_cmp` fields, and `fs_blob_patcher()` applies the same two skips — so `stage=N` and `wide_cmp=0` keep working on blobs too. In particular `patch_widechar_compare` is `stage_idx=2, needs_wide_cmp=true`; p11–p16 (the `wide_cmp=0` per-instruction fallback) are unaffected, so `[fs_codepage] wide_cmp=0` still means "conservative 2-byte compare".
- **M6: the wide-char wildcard matcher is a whole-function replacement.** p18–p26 (12 `wide_cmp=true` instruction entries) were folded into **one** position-independent implementation, `patch_widechar_compare` (820 bytes, hole budget `0x360` = 864 on the tightest shape). It is the encoding-domain-aware `*`/`?` matcher (`*=0x2a`, `?=0x3f`) with recursive backtracking; equivalence with the patched original was proven offline by **executable differential** — 3 shapes × 3000 random cases, `9000/9000` byte-identical results against `apply_group_patch()` (`_audit/_m6_oracle.py`, log `_audit/_m6_diff_big.log`). Locating it uses **two entry-aligned templates** (`fs_cp_p18_wc_func_replace_a` for the AB family, 20 binaries / `_b` for the C family, 16.1.0 only), each an AND of the first 10 words with the PC-relative words wildcarded; both hit exactly once or not at all across all 22 binaries (`_audit/_m6_locator2.py`, `_audit/_m6_harvest_check.py`). **It needs two harvests**, so unlike `patch_str_unicode2oem` it uses two placeholder pairs: the ctx slot (`0xDEAD0001/2`, rewritten as `x3`) *and* the one external callee (`0xDEAD0003/4`, rewritten as `x9`, called via `blr x9`). The callee is harvested by taking its **distinct** out-of-body `bl` target within the first `0x300` bytes — there are **three** `bl` to the same callee, so counting `bl` instructions (rather than distinct targets) would wrongly reject the site; the delta also varies *within* a shape (17.x −0x260 … 22.x −0x250), so it must be read from the `bl`, never assumed. The harvest source is read straight from fs memory (`svcReadDebugProcessMemory`) so a function that lands near a 4 KiB chunk end is not rejected. Self-recursion (`bl <own entry>`) stays a plain PC-relative `bl` and is explicitly allowed by the guard; only *external* `BL` is rejected. Sentinels are located **by content, not by position** — GCC emits the stack-frame prologue before the inline asm — so the guard checks "each sentinel appears exactly once, pairs adjacent, in order".
- Other blobs were audited for the same hazard and are clean: `patch_utf8_to_utf16`, `patch_utf16_to_utf8` and `patch_is_oem_mb_char` reference no fs memory at all; `patch_stringdesc_toupper` reads the `StringDesc` **struct passed in as an argument**, and its offsets (`ptr_left@0x00`, `encode_type@0x10`) are confirmed identical on all 22 binaries (disassembly check: `_audit/_check_field_offsets.py`), as is `ctx[0x48]` bit 1 for the code-page context (`ldrb w9,[x21,#0x48]` + `tbnz w9,#1` everywhere).
- Booting/hang triage: `fs_codepage_patch()` writes a progress marker to `[debug] fs_codepage_patch_result` in `log.ini` *before* each pending patch group (`start → <function-group label> → success`; since P1 the marker names the **function group** — e.g. `p11_p26_WideChar_Compare` — rather than the old semantic stage, and it holds the last group processed, so it points at the culprit function). If fs is broken by a patch it hangs, and sys-patch can no longer write to the SD — so the last recorded value names the culprit group. Per-entry outcomes are also logged: `[fs_codepage] <patch_name> = <result>` for all 22 patterns + 8 blobs, and `[fs_codepage_sites] <patch_name> = 0x<offset>` for every hit site (offset relative to the module base, same frame as `RESOLVED.md`). Escape hatch: `[options] fs_codepage=0` in `config.ini` skips the whole fs codepage patch (all other sys-patch patches still apply), no rebuild required. `[fs_codepage] stage=N` (bisect group by group; applies only entries with `stage_idx < N`, default `6` = all) and `[fs_codepage] wide_cmp=0` (revert the R1c 24-bit name compare to the conservative 2-byte compare) are also preserved.
- RE notes: `fs_encode_fix/*.md` and `plan.md` (Chinese). The **authoritative scheme + implementation write-up for the UTF-8 Chinese-path patch is `fs_encode_fix/re_utf8_patch_final.md`** (patch inventory, ASLR discipline, per-function notes, guard, triage, limitations) — read it first. Incident post-mortems: `re_boot_hang_2026-09-15.md` (boot hang) and `re_path_not_found_2026-09-15.md` (enumerate-but-cannot-open). Struct offsets: `fs_structs.h` (packed, `_Static_assert`-checked); analysis conclusions: `re_analysis.md`; improvement plan: `re_improve_plan.md`. Dev helper for fs RE: `fs_encode_fix/_fs_dis.py` (`sites` / `range` / `word` / `adrp`) — needs capstone, so run it with the managed venv python; the former one-off `_dis_*` / `_diag_*` scripts were folded into it and into the build guard.
- **Firmware compatibility audit: `fs_encode_fix/fs_fw_audit.py`** — one command from a firmware image to "do the fs offsets still work, and what are the new ones". Subcommands: `all <firmware zip|dir>` (unpack → audit → `report.md`), `check`, `audit`, `unpack`, `holes`. It automates the whole `ns_reverse/cmd.txt` chain: scan the cnmt NCAs for `Title ID == 0100000000000819` with `hactool -i` (NCA headers are *encrypted*, so raw byte scanning cannot see the title id) → `nstool` the cnmt for the BootImagePackage NCA id → `hactool --romfsdir` for `nx/package2` → `hactool -t pk21 --ini1dir` → `hactool -t kip1 --uncompressed`. Then it parses every fs patch point out of the generated table (historically the `fs_patch_function` byte arrays in `main.cpp`; today the `fs_cp_patterns`/`fs_codepage_blobs` entries) and relocates each one with layered clues (same offset → unique exact match → anchor-vote over a baseline window → interval-vote when many points share one block shift), scoring candidates by **semantic** window match (PC-relative displacements such as `B`/`B.cond`/`CBZ`/`TBZ`/`ADR`/`ADRP`/literal `LDR` are masked out — otherwise a pure block shift looks like a code change). Statuses: `OK` / `MOVED` / `FUZZY` / `AMBIGUOUS` / `LOST`, plus a **`cmp 精确命中 N/31`** column. Note what that number means since the pattern rewrite: the tool derives each point's baseline `site` and a `cmp` **fingerprint** by matching the new table's pattern against the baseline binary (`site = hit + inst_offset`; `cmp` = 4 bytes for instruction points, 16 for blob points), and there is no static `patch` byte array any more (`patch(inst)` builds it at runtime). So `cmp 精确命中` is now a **relocation-health indicator, not the safety gate** — the actual gate is the pattern match itself (uniqueness + `cond`), enforced both by the build guard and by `_audit/_verify_cpp_table.py`. Points whose variant family does not exist on the baseline are reported as "0 命中 → 属其它版本族，正常跳过" and are excluded from the denominator. `holes` re-derives each replacement function's available space by anchor-locating the *boundary* function entry (falling back to validating a projected old hole, then to a prologue heuristic) and compares it against the size taken from `sysmod/sys-patch.elf`'s symbol table.
  - Two Windows/hactool traps it already handles, both of which fail **silently or confusingly**: hactool concatenates `--romfsdir`/`--section0dir` values with `\` while nstool outright rejects a path mixing `/` and `\`, so all tool path arguments are normalised to backslashes and the directories are pre-created (hactool does not create the base directory); and a **compressed** KIP1 has a byte-identical header to a decompressed one, so feeding one in makes every point read as `LOST` — rejected up front with a clear message.
  - Baseline for comparison is `$FS_KIP1`, else `ns_reverse/FS_ghidra_1/bin/19.exfat.FS.kip1`. Verification as of 19.0.1: 29/29 relocated, 0 fuzzy/ambiguous/lost, cmp exact 29/29, all five holes unchanged, `patch_is_oem_mb_char` fills its 0x50 hole exactly (no headroom).
- Ghidra internal types `FsObject` (0x278), `FsDirInfoInternal` (0xAAA), `FsDrvObject` (0x8C8), `FatFileContext` (0xB0), `FatFileContextPart` (0x70), `FsDirInfoObj` (0x690), `FatFileObject` (0x520) and `FatBaseEntry`/`FatClusterCacheNode` are code-derived; the old `/Demangler` `*_demangler` variants and `FsDirInfo`/`FsDirInfoExt` offsets are unreliable. IPC structs (`nn::fs::DirectoryEntry` 0x310, `FspPath` 0x301, `DirectoryEntryType`) follow switchbrew.
- Known issues from RE: `FsDirInfoInternal.lname` is `char[513]` but the patched `PFCODE_Str_Unicode2OEM` has no output bound, so long CJK names overflow into adjacent fields (`aUnicodeName`/state at 0x688); `FAT_MatchWildcardRecursive`/`FAT_MakeShortName`/`FAT_ReplaceShortNameNumber` still treat the `isOEMMBchar` return as a bool (+1 advance).

## Patch-table conventions
- Patterns are byte strings; `.` is the wildcard (`REGEX_SKIP`). `inst_offset`/`patch_offset` are relative to the match; `cond`/`patch`/`applied` are constexpr functions.
- `min_fw_ver`/`max_fw_ver` (and AMS equivalents) gate a pattern; `FW_VER_ANY` disables gating. The `version_skip` config controls whether gating is enforced at runtime.
- Naming/layout rules: comments at `sysmod/src/main.cpp:118`.
- `out/`, `build/`, `*.elf`, `*.nsp`, `*.ovl`, `*.txt` are gitignored build artifacts, not source.
